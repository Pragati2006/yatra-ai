## 1. EXECUTIVE SUMMARY

Following Phase 9.1A (which verified that Amadeus Self-Service was decommissioned on July 17, 2026, that no Amadeus credentials exist in the active environment, and that Katra production inventory is unverified), this checkpoint executes a comprehensive, evidence-based audit of:
1. **Existing Accommodation Assets:** An exhaustive audit of existing datasets (`data/hotels_live.csv`, `data/hotels_dataset.csv`, `db.py`), backend routes, agent orchestration paths, and frontend cards.
2. **Real Katra Property Ground Truth:** Cross-verifying real-world Katra accommodation across Shri Mata Vaishno Devi Shrine Board (SMVDSB) dharamshalas, branded commercial hotels, and local budget guest houses.
3. **Global Travel API Landscape (B2B / Wholesaler Audit):** Evaluating Hotelbeds, Expedia Rapid API, Booking.com Partner/Demand API, Agoda, and Sabre/Travelport against student/independent project eligibility, sandbox realism, commercial vetting, and Katra coverage.
4. **Current Application Data-Flow & Provenance Gaps:** Tracing how hotel queries navigate from the React UI to data storage, identifying misleading naming patterns (e.g. `hotels_live.csv`), and detailing data schema deficiencies.
5. **Architectural Target Strategy:** Proposing a provider-independent accommodation service with a normalized schema, pluggable provider adapters, an authentic curated Katra baseline catalog, and transparent user-facing freshness disclaimers.

### Core Audit Finding
The global hotel distribution ecosystem operates almost exclusively under **strict B2B commercial agreements requiring business incorporation, travel agency accreditation (IATA/ARC/GSTIN), and negotiated volume commitments**. No legitimate commercial provider offers permanent, open, free live inventory and pricing APIs for independent student projects without commercial onboarding. Furthermore, **SMVDSB-operated dharamshalas (representing over 60% of Katra's pilgrim accommodation volume) are non-profit religious trust facilities that never distribute through commercial OTAs or GDS networks**.

Therefore, the only technically feasible, honest, and legally sound architecture is a **Hybrid Dual-Tier Accommodation Engine**: an authentic, verified Katra baseline catalog (Tier 2) coupled with pluggable, optional live provider adapters (Tier 1).

### 5.1 Misleading Naming Patterns Identified
1. **`data/hotels_live.csv`:** The word `live` is misleading. The data is 100% static, generated offline by `build_dataset.py`, and shifted to match current dates by `db._build_live`.
2. **`HOTELS_LIVE` in `db.py`:** Gives developers the impression that a background scraper or live sync is active, when it is simply reading a local CSV file.
3. **`rooms_available` column:** Random integers (0 to 30) generated by `random.randint()`. Decrementing this counter upon booking creates the illusion of inventory management, but it has no connection to actual room availability in Katra.

## 6. PROVENANCE AND FRESHNESS GAPS

While Phase 8 implemented solid provenance tagging (`utils/provenance.py`) and frontend indicators (`FreshnessIndicator.jsx`), specific gaps exist in the accommodation domain:

1. **Missing Property Contact & Location Attributes:**
   - `hotels_live.csv` only contains `id, name, category, price_per_night, rooms_available, stay_date`.
   - Lacks physical address, phone numbers, booking website URL, distance from Banganga/Railway station, and check-in/out policies.
   - Forces `HotelMiniCard.jsx` to render hardcoded fallback text (`"Near Katra Main Market"` and `"4.5"`).
2. **Conflation of Published Tariff with Live Availability:**
   - In `db.py`, having a row with `rooms_available > 0` directly implies the room can be booked.
   - In reality, room availability in Katra is dynamic, volatile, and requires live confirmation or on-arrival spot token issuance.
3. **Absence of Provider-Level Attribution:**
   - The current data model does not record whether a property is an official SMVDSB facility, a private hotel, or an OTA listing.
4. **No Multi-Provider Reconciliation:**
   - The system lacks a deduplication engine to reconcile properties appearing across multiple catalogs (e.g. Vivanta Katra appearing in both Amadeus GDS and local directories).

## 7. RISKS AND LIMITATIONS

1. **Legal & Ethical Scraping Risks (SMVDSB):**
   - Scraping `online.maavaishnodevi.org` or attempting to bypass its graphical CAPTCHA violates terms of use, triggers IP blacklisting, and constitutes unauthorized system interference.
2. **Commercial API Cost & Quota Burn:**
   - Live hotel search APIs (Amadeus, Expedia, Hotelbeds) charge per request or enforce strict look-to-book ratios. Unthrottled search queries from conversational agents can rapidly incur severe financial charges or account termination.
3. **Disappointment from Inaccurate Expectations:**
   - Presenting an indicative tariff as a confirmed booking price causes pilgrim distress if the hotel is sold out or rates have surged upon arrival in Katra.
4. **Third-Party Outage Risk:**
   - If the application depends directly on an external API without a local fallback, network timeouts or credential expirations immediately break the core planning flow.

### 8.1 Normalized Accommodation Schema (`AccommodationProperty` & `RoomOffer`)
