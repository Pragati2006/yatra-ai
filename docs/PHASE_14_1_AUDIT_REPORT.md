### Groq Free Tier Constraint Handling
- **Limit:** 8,000 Tokens Per Minute (TPM) sliding window.
- **Prompt Compaction:** Streamlined `CENTRAL_AGENT_SYSTEM_PROMPT` from 7,207 characters to ~1,850 characters (~460 tokens) by eliminating duplicate tool signature summaries.
- **Tool Context Compaction:** RAG chunks returned to LLM context are compacted to 1,200 characters (~300 tokens) while preserving full provenance metadata in the user response envelope.
- **Synthesis Optimization:** In `_execute_llm_tool_calling_turn`, the final synthesis call invokes `active_llm` without re-binding tool definitions, saving ~1,500 tokens per synthesis turn.

## 6. CONTEXT RETENTION & SLOT PERSISTENCE AUDIT

### 6.1 Session Unwrapping Bug Fix
In `agents/conversation_state.py`, `update_conversation_state` originally assumed `current_state` was a flat dict of state keys. When invoked from `central_agent.py` or `orchestrator.py`, it was passed the outer session dictionary `{'session_id': '...', 'state': {'requirements': ...}}`. As a result, requirement updates were lost between turns.
- **Fix:** Added session-level unwrapping:
  ```python
  actual_state = current_state.get("state", current_state) if isinstance(current_state, dict) else {}
  req = dict(actual_state.get("requirements") or {})
  ```
- **Result:** State mutations merge non-null extracted fields cleanly back into `session["state"]["requirements"]`.

### 6.2 Mandatory Slot Detection Logic
In `agents/orchestrator.py` (`detect_missing_mandatory_fields`) and `agents/conversation_state.py` (`evaluate_missing_slots`):
- Previous logic checked `not req.get("start_date")`, which always evaluated to False because fallback default dates were populated at parse time.
- Updated logic checks `not req.get("duration_days") and not req.get("_date_explicit")`, ensuring users are naturally prompted for travel dates or trip duration rather than having a plan auto-generated prematurely.

## 10. REMAINING LIMITATIONS & HONEST DISCLOSURES

1. **Groq Free-Tier Rate Limits (8,000 TPM):** Under heavy multi-turn conversational exchanges, the cumulative token count within a 60-second window can exceed 8,000 TPM. The system gracefully handles this via fallback to `openai/gpt-oss-120b` and subsequent fallback to the deterministic orchestrator. For high-volume production, upgrading to Groq Developer Tier or provisioned throughput is recommended.
2. **Android Streaming Limitation in Expo Go:** While the web client streams tokens progressively via SSE, the Android app under Expo Go relies on complete message fetch. Progressive streaming on mobile requires migrating from Expo Go to an Expo Prebuild native runtime with streaming support.
3. **Emergency vs Continuous Mobility:** The system now factually explains that free wheelchairs are for emergency clinic transfers, whereas palkis and battery cars are required for the full 13 km trek.
4. **Human Booking Gate Maintained:** Automated execution of bookings is strictly blocked until explicit human authorization is granted (`execute_authorized_booking`).
